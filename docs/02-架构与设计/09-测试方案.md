# k8s-ai 测试架构设计

- 版本：v3.0.0
- 日期：2026-08-12（首版） / 2026-10-08（补齐二期、三期）
- 状态：一期~三期已封版（2026-10-08，v3.0.0 基线）；四期为规划口径

## 1. 测试目标

k8s-ai 的核心风险集中在权限与安全边界：读操作自动执行、写操作审批放行、
Secret 值永不进入 LLM / 会话 / 审计。测试的目标是证明这些边界在代码层被强制
执行，并保证扫描、诊断、Agent 循环、审批与创建流程在正常与异常路径下行为正确。

一期至三期的封版已交付以下能力，测试需覆盖：

- 一期：只读扫描与诊断。
- 二期：自然语言 Agent、审批写操作、会话与会话流。
- 三期：资源创建（create_resource 两阶段 dry_run→apply）与运行中取消。

## 2. 分层测试策略

| 层级 | 关注点 | 主要对象 |
| ---- | ---- | ---- |
| 单元 | 单模块正确性、失败收敛、脱敏 | `internal/kubernetes`、`scanner`、`rule`、`evidence`、`diagnosis`、`llm`、`report` |
| 单元（二期） | Agent 循环、审批决策、会话、取消 | `internal/agent`、`approval`、`session`、`tools` |
| 单元（三期） | 创建风险评估、提案、Secret 值隔离 | `internal/approval/create_risk.go`、`create_proposal`、`secret_values.go` |
| 集成 | 服务编排、SSE 扇出、会话存储、平台能力与红线 | `internal/server`、`internal/session/store.go`、`internal/sessionapi`、`tests/platform` |
| 架构/安全 | 依赖分层、写方法落点、Secret 泄漏 | 架构测试 + AST 断言 + 泄密扫描 |
| 端到端 | 真实集群上读/写/创建 | 一次性真机环境，人工值守 |

## 4. 审批与安全边界测试

### 4.1 Policy.Evaluate 决策序

测试必须锁定以下决策链，不得随意调整顺序：

1. Shell 语法 → 无条件人工审批。
2. ReadOnly → 自动执行。
3. smart grant → 自动。
4. SkipPermissions → 自动。
5. !RequireApproval → 自动。
6. 其余写操作 → 人工审批。

### 4.2 写方法落点（架构测试）

AST 断言持续保证只有 `internal/executor` 允许变更式 client-go 调用；
三期 create 写路径同样收敛在该层。

### 4.3 Secret 值隔离

循环测试从证据、LLM 请求、会话文件、审计文件四个去处断言 Secret 内容值
永不可达；元数据/键级读取（键名、类型、immutable）允许。

### 4.4 运行中取消

`TestCancelActiveRun` 覆盖运行中停止：按 session 记录 `context.CancelFunc`，
取消后 SSE 正常终止、会话状态机迁移到 cancelled。

## 5. 架构与依赖分层

保持所有业务逻辑不依赖 CLI，CLI、Server、Web UI、CronJob 复用同一批应用服务。
架构测试校验服务层不 import 客户端展示层，扫描、规则、证据、诊断分层不被破坏。

## 6. 压力与稳定性

- 大集群扫描：worker pool 上限、单资源超时、阶段预算。
- LLM 流式：背压、扇出到多个 SSE 订阅人不互相阻塞。
- 审批等待：waiting 状态不占用 Agent 执行 slot。

## 7. 准出标准

封版（一期~三期）需满足：

- `go test ./...` 全部通过。
- `go vet ./...` 无告警。
- 关键模块（scanner、approval、session、tools、agent、webui）单测齐全。
- 架构测试 + Secret 泄漏测试通过。

四期（企业化平台化）上线前补充租户隔离与权限治理相关测试。
