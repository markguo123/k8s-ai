## 1. 目标与范围

目标：把四期 Web Shell 从"功能可跑"提升到"企业级可交付"——过程可读（工具执行看得懂）、层级清晰（深浅主题与海拔体系）、交互顺手（跟随、定位、折叠、持久化）。

## 2. 设计令牌与主题系统（ADR-033）

### 2.1 现状核查

- `web/src/styles/index.css` 已有 `--app-*` 令牌层与 Element Plus 变量覆盖，取值与原型 `:root` 一一对应（深色底座）。
- **没有**任何主题切换：无 `data-theme`、无 `prefers-color-scheme`、无持久化（仅引入了 EP 的 `dark/css-vars.css`）。 

### 2.2 约定

| 项 | 约定 |
| --- | --- |
| 属性 | `<html data-theme="dark|light">`（应用令牌）与 `<html class="dark">`（Element Plus 深色变量）**同步**设置，避免两套变量各说各话 |
| 模式 | `light` / `dark` / `system`；**默认 `dark`**（产品基线是深色控制台，"跟随系统"是可选模式而非默认）；`system` 模式监听 `matchMedia('(prefers-color-scheme: dark)')` 的 `change` 事件 |
| 持久化 | `localStorage['k8s_ai_theme_mode']`；缺失时按默认 `dark` 处理 |
| 首屏防闪烁 | `index.html` 内联脚本（早于样式与 bundle）读取 localStorage 与媒体查询，同步写 `data-theme` 与 `.dark`，禁止等 Vue 挂载后再切 |
| 令牌分层 | 基础色（bg/surface/surface-2/elevated/sidebar）、边框与分割线、文本三级、语义色（success/warning/danger/info + soft）、强调色、阴影/内发光、圆角、等宽字体 |
| 亮色令牌 | 与深色同名同义，仅取值不同；**不允许**组件里出现写死的十六进制颜色，一律走令牌 |
| 海拔体系 | 全局背景 → 侧边栏 → 会话列表 → 聊天空白区 → 卡片，五级灰度差；优先用微弱阴影/内发光而非生硬边框 |
| 滚动条 | 自定义纤细滚动条（WebKit `::-webkit-scrollbar` + Firefox `scrollbar-width: thin`），深色为深灰、hover 显影；亮色同步；杜绝系统白色滚动条 |
| 排版 | 正文 `line-height: 1.6`；区块留白按 4/8/12/16/24 令牌；标题层级在卡片内收小，不做页面级大标题 |

### 2.3 令牌落点与已登记清单（实现后回写，ADR-033 第 4 条要求）

**落点分工（同一件事不要在两处定义）**

- `web/src/styles/index.css`：`--app-*` 基础令牌与 Element Plus 变量覆盖的深色底座（与原型 `:root` 同源）。
- `web/src/styles/tech-theme.css`：P7 新增令牌层、全局海拔底色、跨组件共用动效与胶囊（`.state-pill`）。
- 组件形态（侧栏、顶栏、会话卡、工具卡、输入区…）一律写在各组件 `<style scoped>` 内。

**为什么组件形态不能写在 `tech-theme.css`**：Vue 的 scoped 样式会编译成 `.cls[data-v-xxx]`，权重高于全局同名类选择器；写在全局文件里的组件规则会被**静默压制**，表现为"改了没反应"——这正是最初页面显得扁平死板的根因。

**已登记令牌（P7 落地后）**

| 分组 | 令牌 |
| --- | --- |
| 基础色 | `--bg` `--surface` `--surface-2` `--surface-hover` `--border` `--hairline` `--text` `--muted` `--faint` |
| 强调与语义 | `--accent` `--accent-2` `--accent-3` `--accent-soft` `--accent-2-soft` `--accent-border` `--accent-2-border` `--neutral-soft`；语义色 `--app-success` / `--app-danger` / `--app-warning` / `--app-info` 及其 `-soft`、`-border` 变体 |
| 海拔与画布 | `--canvas`（聊天画布，比侧栏/会话列表亮一档）`--canvas-inset`（微弱内发光）`--shadow` `--panel-shadow` |
| 光效与品牌 | `--glow-accent` `--glow-cyan` `--brand-gradient`（`linear-gradient(135deg, #6366f1, #a855f7)`） |
| 悬浮面 | `--card-bg` `--card-bg-hover` |
| 形状与滚动条 | `--app-radius` `--app-radius-sm` `--app-scroll-thumb` `--app-scroll-thumb-hover` |

所有令牌均给出亮/暗两套取值（`html[data-theme='light']` 下重声明），并统一映射为 `--app-*` 供组件读取；组件不得写死颜色。

## 3. 布局与滚动

经典双栏：左侧会话列表**固定宽度、独立上下滚动**；右侧聊天区独立滚动，底部输入区常驻。

### 3.1 高度链契约（ADR-035，实现时踩过坑，必须按此写）

| 层级 | 规则 | 作用 |
| --- | --- | --- |
| `html` / `body` / `#app` | `height: 100%` | 视口高度的起点 |
| `.app-shell`（el-container） | `height: 100%` | 横向骨架，侧栏与内容区拉伸到满高 |
| `.app-body`（纵向 el-container） | `min-height: 0` | **允许纵向收缩**，否则被内容顶高 |
| `.app-main`（el-main） | `min-height: 0` + `display: flex; flex-direction: column` | 给路由页面一个高度确定的容器 |
| `.chat-page` | `flex: 1 1 0; min-height: 0; overflow: hidden` + `grid-template-rows: minmax(0, 1fr)` | 双栏占满可用高度，不随内容增长 |
| `.conversation-list` | `height: 100%; min-height: 0`；内部 `.list-body` 为 `flex: 1; min-height: 0; overflow-y: auto` | 左栏固定宽度、独立滚动 |
| `.chat-main` | `flex-direction: column; min-height: 0`，内含 `chat-head` / `chat-body`(`flex: 1; min-height: 0; overflow: hidden`) / `chat-composer`(`flex: none`) | 消息区独立滚动，输入区不随消息滚动 |

**两个必须避开的写法**（都真实发生过）：

1. 不要给 `.chat-page` 写 `height: 100%`：父级 `.app-main` 的高度来自 flex（其 `height` 属性仍是 `auto`），百分比会解析成 `auto`，页面被内容撑高、输入框被顶出视口。
2. 不要依赖网格的隐式 `auto` 行：必须显式 `grid-template-rows: minmax(0, 1fr)`，否则行按内容高度撑开，同样把输入框挤出视口。

### 3.2 自检方法（改布局后必查）

造 40 条会话 + 长消息，控制台应同时满足：

- `document.documentElement.scrollHeight === window.innerHeight`（无页面级滚动）
- `.composer` 的 `getBoundingClientRect().bottom <= innerHeight`（输入区常驻可见）
- `.list-body.scrollHeight > .list-body.clientHeight`（左栏确实在独立滚动）

### 3.3 移动端（≤ 768px）

会话列表改为抽屉：`.chat-page` 退化为单列；`.chat-side` 用 `position: fixed` + `translateX(-110%)` 默认收起，由聊天区顶栏按钮唤出（`.drawer-open` 回到 `translateX(0)`），配 `.mobile-backdrop` 遮罩，选中会话或点遮罩即关闭；抽屉内复用同一组件，不另写一套。

## 4. 会话列表

- 数据范围由后端决定：`user/operator` 只返回自己的会话；`admin` 可查看并操作全部会话。
  前端不从本地缓存拼接或猜测其他用户会话。
- 顶部工具条：新建、搜索、刷新（沿用现有图标风格）。
- 列表项：标题 = 自动提取首条对话意图（无则"新会话"），加粗；状态标签（Done/Idle…）做成小圆角胶囊移到右上角；第二行放"消息数 · 相对时间"浅灰小字；Hover 时右侧滑出操作菜单。
- 三点菜单：重命名、置顶、导出 Markdown、删除。动作后统一 确认弹窗 + Toast + 列表状态同步；**置顶会话始终排最前**（置顶集合内部按最近活跃排序）。
- 后端依赖（不可省略）：会话必须带不可变 `ownerUserId`；置顶需要会话级字段与排序参数
  （`pinned` + `List` 排序）；`/api/v1/sessions*` 的列表、历史、SSE、运行控制与增删改均执行 owner 校验。
- **分享 = 导出 Markdown 文件**（2026-10-15 定案）：把当前会话导出为 `.md` 文件由浏览器直接下载，内容按时间顺序包含 用户提问 / 思考过程 / 工具调用（工具名、参数摘要、结果摘要、状态、耗时）/ 最终报告；**不生成对外链接、不做匿名访问**。导出内容沿用既有脱敏口径（Secret 值与 kubeconfig 永不出现），文件名建议 `k8s-ai-<会话名>-<yyyyMMdd-HHmm>.md`。前端生成 Blob 下载，不新增后端接口；报告内的 Markdown 原样保留，便于贴进工单或周报。
- 标题自动提取：优先取该会话首条 user 消息的前 N 字（去换行、截断加省略号）；无 user 消息时回退到会话名，再回退"新会话"。提取在**后端**完成并随列表返回（避免 chat 与刷新两套逻辑）。

### 4.1 实现口径补充（2026-10-15 晚回写）

- **标题提取的落点**：在列表接口返回时计算（`internal/webui` 的 `sessionTitle`），**不写回 Store**。规则：用户显式重命名过的以其为准；仍是自动名 `Session <id>` 且存在首条 user 文本消息时，取首行前 24 字（超出加省略号）；否则回退"新会话"。因此不存在"用户改名被自动提取覆盖"的问题，前端也不做二次提取。
- **置顶分组分隔带**（对齐 DeepSeek）：置顶会话与普通会话之间必须有可见分隔——首条普通会话 `margin-top: 14px`，与基础 8px 行距合成 22px 分隔带；分隔线用 `::after` 画在这 22px 的中点（`top: -11px`），为两端淡出的渐变线（`transparent → rgba(125,145,185,.45) → transparent`）。**不要用 `::before`**，它已被 hover 左缘流光占用；无置顶或全部置顶时**不出线**（避免悬空横线）。
- **搜索**：会话栏顶部输入框按标题与会话 id 做大小写不敏感过滤，无匹配时走空态（与"暂无会话"文案区分）。
- **折叠开关**：会话栏右上角按钮收起为 56px 图标栏。**折叠态仍必须渲染可点击的展开按钮与真实图标**——P7 期间曾因漏 import 图标导致折叠后按钮"看不见"，现已加组件测试（`ConversationList.spec.ts`）锁定该行为。
- **置顶排序**：由后端在列表接口里排序（置顶优先，组内按最近活跃降序）；前端不重复排序，只负责按 `pinned` 渲染分组与分隔带。

## 5. 聊天区交互与滚动跟随

- 智能跟随：默认跟随最新输出；用户上滑离开底部（阈值 24px）后暂停跟随，并显示"有新内容，回到底部"按钮；点按钮或滚回底部后恢复跟随。实现挂在消息滚动容器上，不依赖 SSE 事件类型。
- **Run Bar**（P2.7 步进器的升级形态）：常驻展示"思考 → 工具 → 观察 → 报告"，当前步骤高亮，已完成步骤自动折叠为摘要；点击某步骤定位到对应卡片。定位要求：每个 step 渲染 anchor（`id="step-<turnId>-<seq>"`），滚动容器对 anchor 设置 `scroll-margin-top` 以避开 sticky 顶栏；Run Bar 自身不遮挡消息（sticky + 半透明 + 高度计入容器 padding）。
- 输入区：外边框 + 聚焦高亮（主色柔光）；模型选择器固定在左下角；"Shell 语法需人工审批"等安全提示降级为极小辅助文字或 Tooltip。

## 6. 工具卡与 tool_result 契约（ADR-034）

### 6.1 现状核查（不一致是既成事实，不是风险假设）

| 路径 | 数据来源 | 后果 |
| --- | --- | --- |
| chat 流式 | `tool.completed` / `observation.created` 的 `result` = `truncateText(tr.Text, 240)`（[loop.go:157](internal/agent/loop.go)） | 只有 240 字截断文本，`detectView()` 常退化为 text/logs，**看不到结构化结果** |
| 刷新后 | 会话消息里存的 `Data: tr.Data`（[loop.go:173](internal/agent/loop.go)） | 有完整结构化数据，能渲染表格 |
| 头部字段 | 会话消息不存耗时/风险 | 刷新后 `duration: null`、`risk: ''`（[MessageTimeline.vue:53](web/src/components/chat/MessageTimeline.vue)），"320ms"必然丢失 |

### 6.2 目标契约

工具结果在**事件流与落库使用同一份结构**：

```json
{
  "tool": "get_pods",
  "summary": "成功 · 12 pods · 320ms",
  "displayType": "table",
  "columns": [{"key": "name", "label": "名称"}, {"key": "status", "label": "状态"}],
  "items": [{ "name": "nginx-7d9f8", "status": "Running" }],
  "raw": { "kind": "PodList", "count": 12 },
  "durationMs": 320,
  "risk": "SAFE",
  "ok": true
}
```

- `summary` **由后端在同一次工具执行时计算并随结果下发/落库**，前端只渲染；禁止前端自算摘要，也禁止 chat 与刷新各算一套。
- `displayType` 由后端声明（`table|kv|events|yaml|logs|text`），前端仅按声明渲染；前端保留"未知类型回退"分支，但不再做启发式猜测。
- `durationMs`、`risk`、`ok` 必须落库（会话消息字段），否则刷新后头部信息不成立。
- `raw` 保留完整原始数据（脱敏后），供"Raw JSON 折叠"展示。

### 6.3 工具卡形态与折叠规则

- 头部：状态点 + 工具名（必要时附短名）+ 命令/参数摘要 + 风险标签 + 耗时 + 复制 + 折叠；**概览只在头部**（如"成功 · 12 pods · 320ms"）。有 `summary` 时头部展示摘要、命令降级为 tooltip。
- body：按后端声明的 `displayType` 渲染；前端保留启发式兜底（后端声明未知时按结构猜），"Raw JSON"折叠保留。
- **后端实现落点**：`internal/tools/view.go` 的 `DisplayType()`（声明渲染形态）与 `ToolSummary()`（取人读摘要首行、截断 200 字符）；`internal/agent/loop.go` 在同一次工具执行时计算 `durationMs`/`risk`/`summary`/`displayType`，写入 `session.Message`（落库）并随 `observation.created` 下发（同源）。
- 折叠默认态：`running` 默认展开；**回合报告完成后，未手动操作过的卡片自动折叠**；`error` 默认展开并展示错误详情。
- 手动状态持久化：`localStorage['k8s_ai_tool_fold:<toolCallId>']`（`'1'` 表示折叠）；手动优先于自动折叠，刷新后保持；回合头部提供"展开全部 / 折叠全部"。
- 虚拟滚动：**未实现（延后，见 §11）**。已定选型（优先 Element Plus `el-table-v2`，其次 `vue-virtual-scroller`，不手写）保持不变，但当前仍用 `StructuredTable`；在接入前不得把"分页/虚拟滚动"作为已完成能力对外承诺。

## 7. Markdown 最终报告主题化

- 标题带图标（h2/h3 前的小图标，纯 CSS/SVG）；表格、代码块、引用、行内代码统一美化；亮暗双主题自适应。
- 保持可读性优先：不加装饰性渐变文字、不做动画；长报告仍是"整块出现"（见 ADR-032：不为流式牺牲正确性）。
- 代码块：语言标签 + 复制按钮（已有）；**长代码块（> 24 行）默认折叠 + 展开/收起**（已实现）。

**实现口径（2026-10-15 回写）**

- 已实现：h2/h3 前的品牌渐变短标（纯 CSS `::before`，无额外依赖）；表格/引用/代码块/行内代码主题化；代码块语言标签 + 复制（事件委托，`DOMPurify` 不放行注入按钮）；长代码块默认折叠并带渐隐遮罩；亮暗两套取值均走令牌。
- 未做（可选，不算缺口）：代码块行号。
- 渲染管线不可变：`raw → marked.parse → DOMPurify 白名单清洗 → 受控容器 innerHTML`；报告正文来自集群数据与模型输出，属**不可信内容**，不得为视觉效果放宽白名单（例如打开 SVG profile）。

## 8. 登录页

- 文案（已实现）：删除"平台内权限由角色与 namespace 授权决定 · 真实权限来自集群 RBAC"，替换为"按授权范围访问集群资源 · 操作全程审计"；保留 K8S-AI 品牌、用户名、密码、登录按钮。
- 背景（口径已收口，2026-10-15 定案）：**沿用既有实现，不再做替换式改造**——canvas 粒子网络（`web/src/views/loginNetScene.js`）+ `web/src/styles/login-tech.css` 的径向渐变 / 细网格 / 低透明光感 / 玻璃卡片 / 聚焦光效。该实现源自一份前端原型草稿（`prototype/login-eg.html`），**该草稿未随仓库保留**，因此仓库内唯一事实来源就是上述两个文件，不要再按"某个原型文件"去找参照。本方案初稿提出的"纯 CSS/SVG、不引粒子库"仅是当时候选，**最终以既有实现为准**；后续如需换成 SVG，必须单独立项，不得在其它任务里顺手替换。
- 约束（仍然有效）：动画尊重 `prefers-reduced-motion`（reduce 下只渲染一帧）；`initLoginNet()` 必须返回 dispose 清理函数，由 `LoginView` 在 `onUnmounted` 释放事件监听 / rAF / 定时器——否则指针视差与定时器会一直挂在 `window` 上，离开登录页后触发空引用报错并叠加定时器；亮色主题同样可用。

## 9. 验收标准

1. 工具结果 chat 与刷新一致（同源 `tool_result`）；头部有摘要，body 有结构化表格。
2. 最终报告后工具卡自动折叠，刷新后保持；手动状态优先并可"展开全部/折叠全部"。
3. 左右双栏独立滚动，底部输入框始终可见；移动端会话列表为抽屉。
4. 会话三点菜单可重命名、置顶、导出 Markdown、删除，均有确认与 Toast；置顶排最前；导出的 `.md` 内容顺序正确且无敏感值。
5. 流式输出智能跟随、可暂停；Run Bar 阶段可点击定位。
6. Markdown 报告视觉现代化，亮暗均正常。
7. 默认深色，支持亮色与跟随系统并持久化，首屏无闪烁；无系统白色滚动条。
8. 登录页无原 RBAC 文案，背景科技感提升，主题适配完整；空状态有引导。
9. 布局高度链自检通过：40 条会话 + 长消息下无页面级滚动、左栏独立滚动、底部输入框常驻可见（自检方法见 §3.2）。
10. 会话栏置顶分组有可见分隔带；折叠后展开按钮与图标可正常渲染与点击。

### 11.3 易错点清单（新页面/新组件必须遵守）

1. 组件形态样式写组件 `scoped`；全局样式文件只放令牌、海拔底色与跨组件共用动效（§2.3 已解释 scoped 权重压制问题）。
2. 百分比高度只在父级高度确定时可用；flex / 网格链路要显式 `min-height: 0`（§3.1）。
3. 网格容器要显式 `grid-template-rows: minmax(0, 1fr)`，不要依赖隐式 `auto` 行。
4. 交互态持久化的 key 必须用稳定标识（`toolCallId`、会话 id），禁止数组下标。
5. 新增令牌必须亮/暗成对并在 §2.3 登记（ADR-033 第 4 条）。
6. 工具结果的摘要与渲染形态由后端计算（ADR-034）；前端不得自算摘要或另起一套类型判断。
