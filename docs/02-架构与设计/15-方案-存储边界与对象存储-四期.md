# k8s-ai 四期方案：存储边界与对象存储（Object Storage）

- 版本：v1.1（2026-10-28）
- 状态：**已签收**（2026-10-28；仅 §18 两条外部待确认项挂起：MinIO AGPLv3 法务口径、现场是否已有对象存储）。已落 ADR-043、决策基线 **D-32**、开发计划 **v1.52** 新增主线 **P8（M8）**，代码从 P8.1 开始。
- 关联：ADR-031 v1.14（配置面）、ADR-037（权限与会话 owner）、ADR-040 v1.2（env 两档）、ADR-042（存储主口径与迁移入口）、D-04/D-19/D-20/D-26/D-31、部署手册 §3.5/§4.9/§4.10

## 1. 为什么现在做（现状逐条可核对）

| # | 现状 | 证据 | 后果 |
| --- | --- | --- | --- |
| 1 | 会话正文整份 JSON 存 MySQL `sessions.data`，且**列表页每次请求全表读正文** | `internal/store/sqlite.go:271` `SELECT data FROM sessions ORDER BY last_modified DESC`；索引列在 `Create`（`sqlite.go:234`）里已同源写好却不被 List 使用 | 会话变多后列表页把整库正文读进内存再反序列化，规模上去必然崩 |

| 7 | 无会话图片/文件上传通道 | 全仓唯一 multipart 先例是技能包 zip（`internal/server/skills.go` `import-zip`） | 附件必须现在就把落点定对，否则又是一次二次搬迁 |

结论：会话、报告、附件三类大载荷现在都压在「行内长文本列 + 容器本地目录」上。搬迁成本随数据量单调上升，**必须在 P4 治理与 P5 记忆/保留写入更多大字段之前定死落点**；同时部署形态（PVC 还是桶）也在这一步钉住。

## 2. 目标与非目标

**目标**

1. 一个 `internal/blobstore` 抽象 + 三个后端（`db` / `dir` / `s3`），业务侧只依赖接口，不感知厂商。
2. 默认后端 `db`：**行为与现在完全一致**（长文本列 + 报告目录兼容），零迁移风险、零配置即可升级。
3. 大载荷三类接入：巡检报告产物、会话附件（P8.7 延后交付但表结构与 API 本期定死）、可选会话正文外置。
4. MinIO 作为默认交付形态进 `deploy/` 与 `install.sh`，S3 兼容面覆盖 MinIO/Ceph/OSS 等私有化对象存储。
5. 把 `retention` 需要的对象生命周期契约（引用计数、可回收枚举、删除）在本方案定死，P5 只实现调度不重新设计。
6. CLI 二进制零影响（§11 硬约束）。

**非目标（本期明确不做）**

- 多副本扩缩前置项（SSE sink 与 `ProposalStore` 外移 Redis/DB）：维持单副本，登记五期。
- 客户端加密（SSE-C/KMS）、桶版本化、跨区复制、生命周期规则托管、CDN 直传大文件。
- Skill assets 外置（现在元数据落库已够用）、向量库/嵌入存储、Prometheus 远端存储。
- 把 `sessions.data` 从 MySQL 搬走：MySQL 仍是会话**唯一权威源**，桶只承载可重算或已双备份对象（§3 原则 4）。

## 3. 设计原则

1. **接口无厂商性**：`blobstore.Store` 只允许 S3 通用语义（对象读写、前缀列举、条件写、presign）。禁止 bucket policy service、replication、object lock 等 MinIO 私有 API。
2. **默认后端零行为变化**：`platform.blobs.driver` 默认 `db`。未显式改配置的环境，升级即无感，`config validate` 与启动日志明示当前后端。
3. **引用列，不搬列**：业务表新增可空引用列指向对象，不做历史数据 backfill。老库升级只加列建表，无数据搬迁、无停机窗口。
4. **事实源唯一**：小载荷 inline 留 DB，保证 `mysqldump` 单文件自洽可恢复；桶里只放报告/导出/附件这类可重算或用户自有备份的对象。
5. **内容寻址**：key 内含 `sha256`，同一字节序列天然去重、`Put` 天然幂等（重跑扫描不产生新对象），失败重试无需事务协调。
6. **先内容后引用**：写顺序永远是「对象写成功 → 同事务写业务行 + 引用计数 +1」。崩溃只留下可回收孤儿对象，绝不留下悬空引用。
7. **CLI 简单性优先于平台一致性**：见 §11，CLI 只允许 `off|dir`，永不接触 endpoint/AK/SK。

## 4. 接口定义（新增 `internal/blobstore`）

```go
package blobstore

// Ref 是对象的自描述元数据。审计、事件、日志只允许携带 Ref，不携带内容。
type Ref struct {
	Key       string    `json:"key"`
	SHA256    string    `json:"sha256"`
	Size      int64     `json:"size"`
	MediaType string    `json:"mediaType"`
	UpdatedAt time.Time `json:"updatedAt"`
}

type PutOptions struct {
	MediaType string // 空则按 key 扩展名推断，再空回落 application/octet-stream
	SHA256    string // 可选：调用方已知摘要，写完做校验，不符即失败
}

type Store interface {
	Put(ctx context.Context, key string, r io.Reader, opts PutOptions) (Ref, error)
	Get(ctx context.Context, key string) (io.ReadCloser, Ref, error)
	Stat(ctx context.Context, key string) (Ref, error)
	Delete(ctx context.Context, key string) error
	// List 按前缀流式回调；回调返回 error 即中止。禁止全量入内存。
	List(ctx context.Context, prefix string, fn func(Ref) error) error
	Driver() string // "db" | "dir" | "s3" | "off"
	io.Closer
}
```

可选能力用独立小接口声明，调用方按类型断言取用，不污染主接口：

```go
// Presigner 仅 s3 后端实现；dir/db 走服务端流式下载端点。
type Presigner interface {
	PresignGET(ctx context.Context, key string, ttl time.Duration) (string, error)
}

// Maintainer 由 db/dir/s3 三后端统一实现：启动期就绪保障与垃圾回收。
type Maintainer interface {
	Ensure(ctx context.Context) error // s3：HeadBucket→CreateBucket 幂等；dir：目录+flock 校验
	GC(ctx context.Context, olderThan time.Time) (GCResult, error)
}

type GCResult struct {
	Collected []Ref
	Freed     int64
}
```

哨兵错误（调用方按语义分流，不做字符串匹配）：

```go
var (
	ErrNotFound     = errors.New("blob: not found")
	ErrTooLarge     = errors.New("blob: object exceeds limit")
	ErrKeyInvalid   = errors.New("blob: invalid key")
	ErrDisabled     = errors.New("blob: storage backend disabled")
	ErrChecksum     = errors.New("blob: sha256 mismatch")
	ErrLocked       = errors.New("blob: directory backend already in use") // dir 后端 flock 冲突
	ErrUnsupported  = errors.New("blob: operation not supported by backend")
)
```

`driver: off` 时由 `disabledStore` 实现同一接口，所有写返回 `ErrDisabled`；调用方据此把附件/报告端点降级为 `503 明确未启用`，而不是静默丢弃。

装配位置：`internal/cli/server.go` 与 `openPlatformStore` 同层构造，注入 `server.NewWithPlatform`、`service.NewChat` 的可选字段（未注入即 `off`），保持既有签名兼容。

## 5. key 规则、去重与长度约束

```
{prefix}/{category}/{ownerScope}/{bizPath...}/{sha256}{ext}
```

| category | key 模板 | 说明 |
| --- | --- | --- |
| `reports` | `k8sai/reports/{clusterID}/{scanID}/{sha256}.md` | 同 scan 的 md/json 并列两个对象 |
| `exports` | `k8sai/exports/{userID}/{yyyy-mm}/{sha256}.csv` | 预留，本期只定义不实现写入方 |
| `attachments` | `k8sai/attachments/{userID}/{sessionID}/{sha256}{ext}` | P8.7 交付写入方，本期定结构与 API |

`ValidateKey` 强制（违反即 `ErrKeyInvalid`，与后端无关，在 Store 入口统一校验）：

1. 匹配 `^[a-z0-9._-]+(/[a-z0-9._-]+)*$`；禁止前导 `/`、`//`、`..`、`\`、盘符、URL 编码残留、控制字符。
2. 总长度 ≤ **191**（沿用本仓 `colText` 既有约定：MySQL 渲染 VARCHAR(191)、SQLite 渲染 TEXT，`utf8mb4` 在老行格式下索引上限 767 字节）。`platform.blobs.prefix` 校验 ≤ 32 字符，`userID`/`sessionID` 用现网 ID 时总长约 145，留有余量；超长直接拒绝，不做哈希截断（截断会让 key 失去可读性）。
3. `category` 必须在白名单 `{reports, exports, attachments}` 内。
4. key 的最后一段必须以 64 位十六进制 `sha256` 开头（内容寻址的不变量，GC 与去重依赖它）。

去重语义：`Put` 以 key 为主键覆盖写，写入前 `Stat` 命中且 `sha256` 相同即直接返回既有 `Ref`（省一次传输）；`sha256` 不同则视为调用方 key 构造错误，返回 `ErrChecksum`。

## 6. 后端矩阵与部署形态矩阵

| driver | 载体 | 事务性 | 多副本 | 典型场景 |
| --- | --- | --- | --- | --- |
| `db`（默认） | `blob_objects.payload`（MySQL `MEDIUMBLOB` / SQLite `BLOB`） | 与业务行同库同事务，**最强** | 随 DB | 默认升级、小规模、要求「一个 dump 全恢复」 |
| `dir` | 本地/挂载目录 | 无跨库事务，靠先内容后引用 | **必须单副本**（flock 硬约束）；RWX 只承诺 write-once/read-many | 单机 appliance（`sqlite + dir`）、离线交付 |
| `s3` | S3 兼容桶（MinIO 默认交付） | 无跨库事务，靠先内容后引用 + GC | 天然支持 | 平台形态（`mysql + s3`） |
| `off` | 无 | — | — | 只跑 CLI、或明确不要附件/报告产物 |

形态矩阵（与 D-26 两部署形态正交，这里只管存储）：

| 交付形态 | store | blobs | 副本策略 | 备注 |
| --- | --- | --- | --- | --- |
| 单机 appliance | `sqlite` | `dir` | `replicas: 1` + `strategy: Recreate` + flock | 挂 PVC；`dir` 后端在 `replicas>1` 时启动 WARN |
| 平台（默认交付） | `mysql` | `s3` | 本期仍 `replicas: 1`（§18） | MinIO 同 ns 部署或对接现场已有桶 |
| 存量升级 | `mysql` | `db` | `replicas: 1` | 零配置、零搬迁，行为与今日一致 |

`dir` 后端的 flock：进程启动时对 `{dir}/.lock` 取 `flock`（Windows 用 `LockFileEx` 等价实现），被占用即 `ErrLocked` 直接启动失败。这把「不能横向扩」从口头约定变成硬约束，避免运维误配多副本导致静默丢对象。

## 7. 数据模型（schema v6，全部新增可空列/新表）

新增列种类 `colBytes`：SQLite `BLOB`，MySQL `MEDIUMBLOB`（`internal/store/dialect.go` 现只有 `colText`/`colTextMedium`/`colLong`，本方案补 `colBytes`，渲染与建索引规则同 `colLong`——不可建索引、`ALTER` 走已有 `modifyColumn`）。落地方式沿用既有声明式建表：`dialect.go` 的 `tableSpec`/`indexSpec` 增表增列、由 `d.createTable` 双方言渲染，迁移版本与表清单同址维护在 `internal/store/migrate.go`（`sessions` 表规格见该文件 schemaV1）。

### 7.1 `blob_objects`（注册表 + `db` 后端正文载体）

| 列 | kind | 约束 |
| --- | --- | --- |
| `blob_key` | `colText` | PRIMARY KEY（191 上限由 `ValidateKey` 保证） |
| `sha256` | `colText` | NOT NULL，索引 `idx_blob_objects_sha` |
| `size` | INTEGER | NOT NULL |
| `media_type` | `colText` | NOT NULL |
| `category` | `colText` | NOT NULL，索引 `idx_blob_objects_category` |
| `ref_count` | INTEGER | NOT NULL DEFAULT 0，`>=0` 由服务层校验 |
| `payload` | `colBytes` | 可空；仅 `driver: db` 写入，其他后端恒 NULL（注册表语义统一） |
| `created_at` / `updated_at` | 时间 | 现有时间列口径 |

### 7.2 业务表

```
attachments(id PK, session_id idx, turn_id, user_id, name, blob_key, media_type, size, sha256, created_at)
reports(id PK, cluster_id, scan_id, kind, blob_key, media_type, size, sha256, findings, created_at)
```

- `attachments.name` 只存展示名（服务端净化：去路径、控制字符、限 191），真名落 key，永不拼路径。
- `reports.kind ∈ {latest-md, latest-json, daily-md}`，一个渲染产物一行，`scan_id` 允许为空（CLI 本地扫描不入表）。
- `sessions` 增两列：`data_blob_key colText`、`data_size INTEGER`。默认 `''`/`0` 表示正文仍 inline；`platform.blobs.session_data: true` 时才外置。`sessions.data` 列保留不删（兼容 + inline 模式仍用）。

### 7.3 引用计数与生命周期契约（P5 只实现调度）

```go
// internal/store：与业务行同事务调用
func (b *BlobStore) Acquire(ctx context.Context, ref blobstore.Ref) error            // upsert 注册表 + ref_count++
func (b *BlobStore) Release(ctx context.Context, key string) error                    // ref_count--
func (b *BlobStore) ListCollectable(ctx context.Context, olderThan time.Time) ([]blobstore.Ref, error) // ref_count=0 且 updated_at < olderThan
func (b *BlobStore) Forget(ctx context.Context, keys []string) error                   // 删注册表行
```

GC 顺序（本期提供 CLI `k8s-ai blobs gc --older-than 168h`，P5 再接进 Retention 调度）：`ListCollectable` → `blobstore.Delete` → `Forget`。宽限期 `olderThan` 默认 7 天，避免与「刚写入未提交事务」竞争。`Acquire`/`Release` 必须在业务写事务内，确保计数与行一致。

## 8. 配置面

**归属**：全部属静态 `platform.blobs.*`（`internal/config`），与 `platform.store.dsn` 同级；**不登记进 settings 动态键白名单**，配置中心页面不展示。理由：存储后端与桶是启动级形态参数，改它必须重启，且 v1.51 已把动态键 env 覆盖面冻结为 LLM 四键 + ops 四键（ADR-040 v1.2），不能再扩。

```yaml
platform:
  blobs:
    driver: db             # off | db | dir | s3
    prefix: k8sai           # ≤32 字符，参与 key 首段
    dir: ""                 # driver=dir：空则容器内 /data/blobs、CLI ~/.k8s-ai/blobs
    endpoint: ""            # driver=s3：host:port，不含 scheme
    region: us-east-1
    use_tls: false
    path_style: true        # MinIO/Ceph 必须 true
    bucket: k8s-ai
    access_key: ""          # 只允许 env/Secret；config 明文出现即 validate WARN
    secret_key: ""          # 同上
    create_bucket: true     # 启动期幂等建桶
    presign_ttl: 15m        # ≤24h
    max_object_size: 32MiB  # ≤256MiB，超限 ErrTooLarge
    session_data: false     # 会话正文外置开关，默认关
    gc_grace_period: 168h
```

环境变量沿用 `internal/config` 既有机制（`SetEnvPrefix("K8S_AI")` + `AutomaticEnv`，与 `K8S_AI_PLATFORM_STORE_DSN` 同路径）：`K8S_AI_BLOBS_DRIVER`、`_PREFIX`、`_DIR`、`_ENDPOINT`、`_REGION`、`_USE_TLS`、`_PATH_STYLE`、`_BUCKET`、`_ACCESS_KEY`、`_SECRET_KEY`。部署清单只注入 `K8S_AI_BLOBS_ACCESS_KEY`/`_SECRET_KEY`（密钥态）与 `K8S_AI_BLOBS_DRIVER/_ENDPOINT/_BUCKET`（形态参数），其余走 ConfigMap。

`PlatformConfig.Validate()` 追加：`driver` 白名单；`s3` 必填 `endpoint`/`bucket`；`dir` 路径可展开且非空；`max_object_size`/`presign_ttl`/`prefix` 范围；`access_key`/`secret_key` 出现在配置文件时输出 WARN（不 fail，保持灰度可控）；`driver: dir` 且检测到 `K8S_AI_REPLICAS>1` 或显式 `platform.server.replicas_hint` 时输出 WARN。

`config init` 两套模板（P6.12 ③⑧ 已锁定的键集合测试）同步追加本组键，`config init --cli` 的 `cli.yaml` **只追加 `driver`/`dir` 两键**。

## 9. 写入顺序、失败语义与降级

写顺序恒为：校验 → `blobstore.Put` → 同事务（业务行 + `Acquire`）→ 提交。

| 场景 | 行为 |
| --- | --- |
| 启动期 `Ensure` 失败（桶不存在且建桶被拒 / dir 不可写 / flock 冲突） | 进程启动失败退出，`/readyz` 不 ready。宁可起不来，也不要在运行期第一次上传才报错 |
| 附件上传 `Put` 失败 | HTTP 502 + 统一错误信封；不写 `attachments` 行；WARN 日志只带 `Ref`/错误类别 |
| 报告 `Put` 失败 | findings 与既有 DB 写不受影响；报告 API 该条目标记不可用；WARN。兼容期仍同时写 `report.directory` |
| 会话正文外置失败（`session_data: true`） | 回退 inline 写 `sessions.data` + WARN，**绝不阻塞 Agent 回合**（沿用现有一期「落库失败仅告警」口径） |
| `Get` 不存在 / key 无权 | 统一 404，不区分「不存在」与「无权」，避免对象探测 |
| GC 删除部分失败 | 保留注册表行、记 WARN，下轮再收；`Forget` 只在对象确认删除后执行 |

## 10. 安全红线

1. 附件与报告**二进制内容永不进 LLM 请求**。Agent 只拿到 `attachments` 元数据（名称/mediaType/size/sha256）；确需模型读图时由 `platform.blobs.multimodal_enabled`（默认 `false`）+ 模型能力判定后单独开启，本期不开。
2. 审计与事件只落 `Ref`（key/size/sha256/mediaType），沿用既有「只记 key/长度/SHA-256、不落明文」口径；SSE 事件载荷禁止内联对象正文。
3. presigned URL 只在已鉴权的下载端点响应体里返回给会话 owner 或 admin，TTL ≤ `presign_ttl`，**不写库、不进 SSE、不进审计、不进日志**；无 presign 能力的后端走服务端流式代理，同一鉴权。
4. `access_key`/`secret_key` 只走 env/Secret，永不写入 `config.yaml` 明文、`settings` 表、审计。
5. key 净化与 `ValidateKey` 是防穿越的唯一闸门，位于 `blobstore` 入口，三个后端共享，禁止后端各自实现。
6. Secret 值不入 LLM/会话/审计的三期红线不因附件通道放宽；报告正文按「不可信数据」对待，沿用 ADR 既有定界处理。

## 11. CLI 零影响硬约束

1. CLI 可用后端只有 `off|dir`。`chat/scan` 路径**不读取** `platform.blobs.{endpoint,region,bucket,access_key,secret_key,create_bucket}`，构造 blobstore 时按 driver 白名单硬拒 `s3`（显式错误文案，不静默降级为 `dir`）。
2. `~/.k8s-ai/` 必须整体自洽可拷：`cli.yaml` + `k8s-ai.db` + `blobs/` + `reports/` + `sessions/` + `audit/` 全在一处，拷走即带走全部现场数据。
3. 文件在 CLI 永远是主路径，对象写失败只 WARN，不允许因 blob 失败丢本地报告/会话。
4. 不引入 CGO 依赖；S3 SDK 走纯 Go 静态编译，`__build.cmd` 增加 slim 构建（`-tags no_s3`）对照，若体积增幅超 8 MB 则默认构建剔除 `s3` 后端并在 `blobs` 命令里提示。
5. CLI 上报平台仅允许显式 flag（如 `--report-to`），默认关闭。
6. 上述每条都要有门禁用例（§16）。

## 12. 依赖选型与交付合规

- SDK 选 **`github.com/minio/minio-go/v7`**：S3 兼容面最全（path-style、v4 签名、分片、presign 齐备）、纯 Go、依赖轻，比 `aws-sdk-go-v2` 少一大棵依赖树；只使用其 S3 通用子集。
- 交付的 MinIO **服务端**镜像为 AGPLv3。我们只在清单里引用官方镜像、不修改不分发其源码；**需法务确认口径**后再写入默认交付清单，未过审前 `install.sh` 的 `ENABLE_MINIO=false` 为默认值，文档给「对接现场已有 S3 兼容桶」路径（`deploy/example/object-storage-s3.yaml`）。
- 依赖 `go mod vendor`，保持离线构建可用（对齐 ADR-041 可复现构建）。

## 13. 接入点与 HTTP API

| 端点 | 权限 | 行为 |
| --- | --- | --- |
| `GET /api/v1/reports` | 新增 `ReportRead = "report.read"`（命名沿用 `internal/permission/permission.go` 风格） | 分页列 `reports` 表（元数据，不含正文） |
| `GET /api/v1/reports/{id}/content` | `report.read` | 服务端流式代理下载；有 presign 能力时 302 到短 TTL URL |
| `POST /api/v1/sessions/{id}/attachments` | 会话 owner 或 admin | multipart（复用 `skills.go` `import-zip` 的净化/限额范式）→ `Put` → `attachments` 行 |
| `GET /api/v1/sessions/{id}/attachments` | 会话 owner 或 admin | 元数据列表 |
| `GET /api/v1/attachments/{id}/content` | 会话 owner 或 admin | 流式下载或 presign 重定向 |

鉴权复用 ADR-037 三层模型：附件跟随其所属会话的 owner 判定，不新增独立权限位；报告是集群级产物，走权限位。路由沿用 `internal/server/server.go` 现有 Go 1.22 方法+路径模式注册风格，并在 `internal/server/permission.go` 登记。

CLI 侧：`k8s-ai blobs {stat, get, put, gc}` 三个动词起步（诊断用），`scan` 报告在 `driver != off` 时额外产出一份对象并在终端打印 `key`。

## 14. 部署面

- `deploy/base/minio.yaml`：StatefulSet（`replicas: 1`，`volumeClaimTemplates` 走 `STORAGE_CLASS`，为空则 `emptyDir` 并 WARN）+ headless Service + Service + `minio-credentials` Secret 模板（占位值，禁止真值）。
- `deploy/example/object-storage-s3.yaml`：外部/现场已有桶接入示例（`K8S_AI_BLOBS_*` 全键占位）。
- `deploy/allinone/deployment.yaml` 与 `deploy/separated/deployment.yaml`：追加 `K8S_AI_BLOBS_*` envFrom（Secret + ConfigMap），`/reports` 与 `/data` 在 `driver: s3` 时可去掉 PVC 依赖，清单注释写明三种后端各自需要的挂载。
- `install.sh` 追加参数：`BLOBS_BACKEND`（默认 `db`）/`BLOBS_ENDPOINT`/`BLOBS_BUCKET`/`BLOBS_ACCESS_KEY`/`BLOBS_SECRET_KEY`/`ENABLE_MINIO`（默认 `false`，待法务口径）/`MINIO_STORAGE_SIZE`。密钥沿用 `K8S_AI_ENC_KEY` 同款幂等语义：已存在则复用、缺失才生成并本地备份、轮换走 `--rotate`。
- `install.sh` 两条互斥校验（缺省即拒绝，不猜）：
  1. `ENABLE_MINIO=true` 隐含要求 `BLOBS_BACKEND=s3`，否则直接报错退出（否则会出现「装了 MinIO 但产品不往桶写」的假配置）；
  2. `BLOBS_BACKEND=s3` 且 `ENABLE_MINIO=false` 时强校验 `BLOBS_ENDPOINT`/`BLOBS_BUCKET`/`BLOBS_ACCESS_KEY`/`BLOBS_SECRET_KEY` 四项齐备。
  两条校验同时写进 `platform.blobs.*` 的 `config validate` 规则（§8），使 `install.sh` 与手工 apply 清单得到同一个判据。
- 迁移：v6 走既有 `k8s-ai db migrate` 与 `deploy/base/db-migrate-job.yaml`，无 backfill。

## 15. 兼容与迁移

1. 老库升级只执行「建 3 张表 + `sessions` 加 2 列 + `schema_migrations` 记 6」，SQLite/MySQL 双驱动各跑一遍门禁。
2. `report.directory` 在 `driver != off` 时**继续写**（兼容 CLI 与已有运维脚本），`reports` 表与桶是新增副本；文档明确「桶为权威产物、目录为现场副本」，二期版本再评估收敛目录写入。
3. 未启用 blob 的环境行为逐字节不变：`sessions.data` 仍 inline，无新表被写入，`/api/v1/reports` 返回空列表并带 `driver: off` 提示。
4. 回滚路径：`driver` 改回 `db` 即停止外部写；已入桶对象成为孤儿，由 GC 或人工处理，不影响会话读取（引用列只在 `session_data: true` 时才被读）。
5. **`db` 后端的选型判据**：`db` 把体积压力从「必丢的 emptyDir」转为「可查可备份的 MySQL 行」，不是把问题藏起来。量级参考：一次 533 Pod / 47 namespace 巡检（真机实测规模）产出的 md + json 约几百 KB 到几 MB，靠 §7.3 GC + P5 Retention 回收，中小规模（百级会话、周级保留）完全可用。出现下列任一情况就切 `s3`：报告月增稳定超过数 GB、需要把产物生命周期交给对象存储生命周期规则、DBA 对 `MEDIUMBLOB` 表膨胀有明确红线。`session_data: true` 只在 `s3`/`dir` 上建议开启，`db` 后端下保持 `false`（否则等于把大正文换个表再塞回 MySQL，只剩去重收益）。

4. blob 配置属静态 `platform.blobs.*`，不进动态键白名单、配置中心页面不展示。
5. CLI 只用 `off|dir`。
6. P8.7 附件上传延后 v4.2。

**待确认（阻塞项，需现场/法务给结论）**
