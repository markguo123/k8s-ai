# k8s-ai 前端设计方案（四期·平台化）

> 面向整个 k8s-ai 产品的前端设计基线。配套可交互原型：本目录 `index.html`（浏览器直接打开，无构建）。
> 本文是**设计讨论稿**，原型定稿前不进入 `web/` 实现；原型出现不合理处，先改本文，再改原型，最后落地。

## 1. 目标与范围

把 k8s-ai 从"单页聊天工具"演进为**企业级 K8s AI 运维工作台**：一个登录入口、一套统一视觉、按角色划分的工作区 / 治理 / 平台管理三块能力，其中**AI 聊天（诊断会话）仍是核心主场景**。

- 覆盖页面：登录、聊天、集群、审批中心、审计、Skill、配置中心、用户与权限、管理控制台。
- 本方案约束前端交互/渲染规则；功能正确性由后端强校验兜底，前端显隐只是 UX（参考 AGENTS：前端隐藏不是安全机制）。

## 2. 现状问题（改版动因）

| 问题 | 表现 | 根因 |
| --- | --- | --- |
| 主题不统一 | 侧栏分组展开白色、整体色彩零散 | 浅色内容 + 深色侧栏拼贴，无统一设计令牌 |
| 工具展示原始 | 工具结果整段裸 JSON `<pre>` | 新 UI 未复用三期结构化渲染器 |
| 交互过程乱 | SSE 事件平铺成一条长时间线 | 未按「回合 turn」分组，缺推理面板/工具卡语义 |
| 报告未渲染 | 最终报告以 `{{ }}` 纯文本出现 | 未引入 markdown 渲染与 XSS 防护 |
| 入口缺失 | "新建会话"不弹输入窗口等 | Composer 交互未完成（P2.10） |

## 3. 设计原则

1. **回合即叙事**：一个回合 = 提问 → 思考 → 工具执行 → 观察 → 最终报告。UI 以 turn 为单位承载，不做事件平铺。
2. **结构化优先于原始**：K8s 返回默认渲染成 表格 / 键值 / YAML / 日志 的**人类可读**形态；原始 JSON 归入"查看原始"折叠。
3. **状态只看事件**：流式/完成/失败只由 SSE 事件驱动，不猜状态（对齐 P2.6 约束）。
4. **安全默认**：Secret 值 / kubeconfig / API key 永不进时间线、摘要、报告与日志；前端展示仅"脱敏+隐显"，不做鉴权。
5. **信息密度分级**：过程卡片默认折叠保留现场，结论区始终可读；思考框推理中展开、报告后折叠。

## 4. 信息架构与导航

### 4.1 侧栏（三组分栏，对齐决策 D-15）

| 分组 | 页面 | 说明 |
| --- | --- | --- |
| 工作区 | 聊天 | 核心主场景，默认落地页 |
|  | 集群 | 集群连接、当前离线态、工作量总览 |
| 治理 | 审批中心 | 待办（本人自确认 + 白名单自动）与历史、决策解释 |
|  | 审计 | 可过滤的操作链路回放 |
| 平台管理 | Skill | Builtin/Custom/ThirdParty 平台模型 |
|  | 配置中心 | 模型/Skill/Approval/Memory/Retention/MCP/运维 分组配置 |
|  | 用户与权限 | 用户×角色、namespace 授权、销毁委派 |

- 右上角 User Menu：当前用户（角色徽标）、版本号、管理控制台入口（admin 专属，仅摆入口，权限由后端判）、退出。
- 品牌区收敛：左侧栏仅 logo + `K8S-AI`，不再展示版本字样；平台版本收敛到右上角 User Menu 内（每人可见，只读）。
- 成员态、分组收起、激活态高亮；深色侧栏常驻，展开内容与侧栏同色系（修复白块）。
- **双栏可折叠**：主侧栏可整体收起为 60px 图标栏（文字隐藏、tooltip 兜底）；聊天页会话栏可独立收起/展开（常态 240px → 收起 56px 纵向指示），最大化主区可读性。折叠动画 200ms 过渡。

### 4.2 页面蓝图

每个页面遵循：顶栏（标题 + 集群上下文 + 全局动作） → 页面主体。列表页统一 搜索/筛选 + 表格 + 分页信封（对齐 `/api/v1` 分页）。

| 页面 | 关键区块 | 主要状态 |
| --- | --- | --- |
| 登录 | 居中卡片：账号/密码/登录 | 错误提示、加载、重定向目标保留 |
| 聊天 | 会话列表 + 回合时间线 + Composer + Token 用量 | 连接中/重连、流式中、运行中可停止 |
| 集群 | 当前集群卡 + 上传/粘贴 kubeconfig + 连接测试 + 总览 | 未连接 / 校验失败 / 已连接 / 断开 |
| 审批中心 | 待办 Tab（风险/工具/资源/正文）+ 详情 Drawer | pending / approved / rejected / auto |
| 审计 | 滤波器 + 时间线 | 按 user/cluster/session/event/time 过滤 |
| Skill | 卡片网格（来源+启停+校验状态+命中数） | builtin/custom/third-party、enabled、校验中 |
| 配置中心 | 左分组菜单 + 右表单，保存前整批校验 | 未保存变更、敏感键只写不读（value 恒 null） |
| 用户与权限 | 用户列表 + 角色矩阵 + namespace 授权抽屉 + 销毁委派 | 零权限起步、过期回收、RBAC 派生只读提示 |
| 管理控制台 | 系统卡片（任务/集群/Session 统计等） | 只对 admin 可见入口 |

## 5. 聊天核心交互详细设计（重点）

### 5.1 回合（Turn）容器

- 时间线按 turn 分组；同 turn 内：`thinking → tools → report`。
- 回合标题含序号 + 结果摘要（成功/失败/审批中）+ 耗时 + token。
- turn 完成后整组**可折叠**为一行摘要（保留现场，不被长消息淹没）。

### 5.2 思考面板（Reasoning）

- `reason.started`：面板展开，region 激活，"正在思考…" + 流式 `reasoning-delta`。
- `reason.completed`：内容保留；**报告出现后**面板折叠为摘要（推理中展开、报告后折叠——对齐需求）。
- 与最终报告分离：思考过程不进报告；无思考时不占位。

### 5.3 工具卡（ToolCallCard）

- 头部：状态点 + 动作名（`shortName`，kubectl 取子命令）+ 命令摘要 + 风险标签 + 耗时 + 复制 + 展开/收起。
- 默认折叠为摘要；**展开后结构化渲染**（见 §6），折叠层保留"查看原始 JSON"。
- `tool.completed`（ok）→ completed 样式，结果立即展开并保持；失败 → error 样式 + 错误条。
- Secret：键指纹（键名 + 长度/sha256 前 16 位）展示，值永不回显。
- `create_resource` 专属：展示提交的 manifest（与实际提交一致）+ 两段式 dry-run→apply 状态。

### 5.4 审批卡（ApprovalCard）

- 风险 + Tool + 参数摘要 + 目标资源 + 命中策略（Grant/SAR 结论）+ 原因。
- 操作：自确认/审批/拒绝；白名单自动通过显示 AUTO 徽标；高危/shell 永不自动。
- 无权用户**不显示按钮**（但后端仍强校验）；Secret 占位输入只提交一次、不入历史。

### 5.5 Composer 与发送（P2.10）

- 底部固定：多行输入框（Enter 发送 / Shift+Enter 换行）+ 模型选择 + 发送（空闲）→ 运行中变「停止」。
- "新建会话"即聚焦空输入框，可直接输入。
- 会话级 Token 用量浮标（右下角，随 `answer` 事件 usage 更新，不含敏感数据）。
- 断线自动重连 + 连接状态徽标。

## 6. 结构化渲染规范（人类可读，替代裸 JSON）

三期老 UI 已具备该能力（`internal/webui/index.html` 的 `tl*` 渲染器），本方案将其**组件化**落到 `web/src/components/chat/render/`，不照搬其样式、保留其能力：

| 老 UI 能力 | 类型识别 | 新组件 | 渲染 |
| --- | --- | --- | --- |
| `renderToolDataTable` | `data.items` + kind 列配置 | `StructuredTable.vue` | 按 kinds 选列、智能列探测、状态 Pill |
| `renderToolKv` | 对象单条 | `StructuredKv.vue` | 键值表，`phase/status/state` 着 Pill |
| `renderToolEvents` | `events/conditions` | `StructuredEvents.vue` | 时间/类型/原因/消息 表 |
| `renderYamlBlock` | 嗅探 YAML（`apiVersion:` 头） | `YamlBlock.vue` | 键/值/字符串/数字上色 + 行号 + 复制 |
| `renderLogsBlock` | 嗅探日志（时间戳/level/panic） | `LogBlock.vue` | 时间戳/级别着色 + 行号 + panic 高亮 |
| `markdown()` | 报告 / answer | `MarkdownView.vue` | marked 解析 + DOMPurify 白名单（§7） |

- 自动嗅探：YAML → 日志 → 纯文本，`stripUntrusted` 清 `<untrusted_k8s_data>` 包装。
- 表格列配置表 `TL_COLUMN_LABELS` / `TL_LIST_COLUMNS` 迁移为 TS 常量模块。

## 7. Markdown 与 XSS 方案

- 引入依赖：`marked`（解析）+ `dompurify`（白名单清洗）。不再手写 markdown 解析器。
- 渲染管线：`raw → escapeHtml 可选 → marked.parse → DOMPurify.sanitize → 挂载 innerHTML`（仅作用在受控组件内）。
- 覆盖语法：h1–h6、有序/无序列表、表格、引用、代码块（带复制）、链接（`target=_blank rel=noopener`）、内联粗斜体。
- 红线：报告/摘要/工具正文里出现的 Secret 值在**上屏前**已被后端或前端脱敏，markdown 不做二次信任。

## 8. 视觉规范

- 基调：企业级运维控制台。默认**深色**（与现有深色侧栏同系延伸，消除白块），另一套浅色预设，主题令牌驱动。
- 令牌（草案，原型落地后冻结）：内容底色 `--bg`、表面 `--surface`、边框 `--border`、主文本 `--text`、次要 `--muted`、主色 `--accent #6366f1`、成功/警告/危险/信息状态色、半径 8–10px、间距 4/8/12/16/24、等宽字体 JetBrains Mono/Consolas。
- 状态色语义：运行中=accent+脉冲、成功=green、失败/拒绝=red、待审批/Pending=amber、AUTO=info。
- 通用组件沿用 Element Plus；新渲染组件为纯 Vue/TS，不引入额外 UI 库。
- 布局可折叠状态：主侧栏收起为图标栏、会话栏收起为纵向指示（两个状态均为「折叠」语义，非缺失组件），保证信息始终可达。

## 10. 落地与四期任务映射

- 本设计与原型对应四期 `P2.7–P2.11`（聊天核心交互与三期行为回归），P2.12 测试门禁一并覆盖新组件。
- 推进顺序（建议，待拍板）：① 本文 + 原型评审定稿 → ② 按 §6 组件化（纯前端，不阻塞后端）→ ③ P2.10 Composer、P2.13 Token、其余页面骨架 → ④ 三期行为回归 + 测试门禁。
- 不涉及 `web/` 之外的后端改动项；如果原型阶段发现服务端事件缺字段（如 turn 摘要、usage 字段），单独开 P2.x 增量任务，不顺手改后端。
