# k8s-ai 构建与测试手册（Linux / Windows）

> 版本口径：DEV-v4.0.0（四期开发中，临时形态）
> 覆盖：后端 Go 编译、前端 Vue 构建打包、后端服务启动（Linux / Windows 双场景）、
> 前后端测试门禁、常见故障定位。

---

## 0. 平台运行形态

企业平台只保留一个后端主进程 `k8s-ai server`（形态 A 内嵌 SPA；形态 B 下为纯 API 后端，
前端由独立静态服务承载）。认证、Session、SSE、集群、配置、用户与审批全部在同一进程装配：

| 进程 | 命令 | 默认端口 | 当前职责 |
| --- | --- | --- | --- |
| 平台后端 | `k8s-ai server` | `:8080` | `/api/v1`（登录鉴权 / 集群 / 配置中心 / 异步扫描），不托管前端静态资源 |
| 前端开发服务器 | `npm run dev`（`web/`）| `5173` | Vue SPA；`/api/v1` 代理到 `server` |

> 部署形态见 `01-部署与安装.md` §4.9：**形态 A 一体化（默认）** 与 **形态 B 前后端分离（可选）**。
> 形态 A 由 `k8s-ai server` 单进程内嵌 SPA（`go:embed web/dist`）同源交付；形态 B 由独立
> `k8s-ai-web`（Nginx + dist）托管前端、后端关闭静态路由只提供 API。本文描述本地开发、
> 构建与测试方式；两种生产形态的部署、升级与回滚见部署手册。

## 1. 环境准备

### 1.1 工具版本

| 依赖 | 最低/建议 | 备注 |
| --- | --- | --- |
| Go | ≥ 1.26（go.mod 为 1.26.0） | macOS/Linux/Windows 均可；SQLite 为 pure-Go（modernc），无需 gcc |
| Node.js | ≥ 20，建议 22 LTS 及以上 | 仅构建/运行新的 Vue 前端需要 |
| npm | 随 Node 自带 | |
| Kubernetes 集群 | ≥ 1.27 | 只读 kubeconfig 即可跑通大部分能力 |
| kubectl（可选） | PATH 或 `kubernetes.kubectl_path` | 二期写操作/Shell 工具需要 |

本机已实测：Go 1.26.7、Node v24.14.0、npm 11.9.0。

### 1.2 前置检查

```bash
go version          # go1.26.x
node --version      # v20+
npm --version
kubectl version --client  # 可选
```

确认能访问目标集群（只读即可）：

```bash
kubectl cluster-info
```

## 2. 后端构建（Go）

### 2.1 Linux 构建

```bash
cd "<仓库根目录>"

# 本机二进制（版本注入）
make build
# 产物：bin/k8s-ai

# 验证
./bin/k8s-ai version
# 期望输出：k8s-ai DEV-v4.0.0 (commit <sha>, built <UTC 时间>)

# 可选：交叉编译仅 Linux amd64（纯 Go，Windows 上也能产出）
make build-linux
# 产物：bin/k8s-ai-linux-amd64

./bin/k8s-ai --help       # 查看全部子命令
./bin/k8s-ai server --help
```

### 2.2 Windows 构建

PowerShell 命令行直接编译：

```powershell
cd "<仓库根目录>"

$v = "DEV-v4.0.0"
$c = (git rev-parse --short HEAD)
$d = [DateTime]::UtcNow.ToString("yyyy-MM-ddTHH:mm:ssZ")
$m = "github.com/k8s-ai/k8s-ai"

go build "-ldflags=-s -w -X $m/internal/version.Version=$v -X $m/internal/version.Commit=$c -X $m/internal/version.Date=$d" -o bin\k8s-ai.exe .\cmd\k8s-ai

.\bin\k8s-ai.exe version
```

或用仓库自带的 CMD 脚本一次产出 Windows + Linux 两个二进制：

```cmd
cd "<仓库根目录>"
__build.cmd
```

产物：`bin\k8s-ai.exe`、`bin\k8s-ai-linux-amd64`。

不带版本号的最简构建（适合纯功能验证）：

```bash
# Linux
go build -o bin/k8s-ai ./cmd/k8s-ai

# Windows PowerShell
go build -o bin\k8s-ai.exe .\cmd\k8s-ai
```

## 3. 前端构建打包（Vue 3 + Vite）

新前端源码在 `web/`，产物输出到 `web/dist`。

### 3.1 安装依赖

```bash
cd web
npm install
```

> 若网络受限，可换镜像源：`npm config set registry https://registry.npmmirror.com`。

### 3.2 开发模式（推荐联调）

```bash
npm run dev
```

默认监听 `http://localhost:5173`，Vite 已配置代理（见 `web/vite.config.ts`）：

- `/api/v1` → `http://127.0.0.1:8080`（平台后端 `k8s-ai server`，含 `/api/v1/sessions*`）

所以浏览器访问 5173 相当于同一域，前端既能登录 `/api/v1`，也能消费 Chat SSE。

### 3.3 生产构建打包

```bash
cd web
npm run typecheck      # 可选：先做类型检查
npm run build          # vue-tsc -b && vite build
```

产物目录：`web/dist/`（index.html + 静态资源）。

本地预览构建产物：

```bash
npm run preview        # 默认 http://localhost:4173
```

> 本地开发走 Vite dev；生产形态 A 将 `web/dist` 内嵌到 `k8s-ai server`，形态 B 由独立静态服务承载。
>
> 若要验证 **形态 B（前后端分离）** 的访问方式，可由 Nginx 托管 `web/dist` 并把 `/api/v1`
> 反代到 `server`；Chat Session 与 SSE 同属 `/api/v1/sessions*`：

```nginx
server {
    listen 80;
    root /path/to/k8s-ai/web/dist;
    location / { try_files $uri $uri/ /index.html; }
    location /assets/ { expires 1y; add_header Cache-Control "public, immutable"; }
    location /api/v1/       { proxy_pass http://127.0.0.1:8080; proxy_buffering off; }
}
```

> 生产形态 B 的 Ingress 路径分流与 SSE 反代要点见部署手册 §4.9.3。

## 4. 后端服务启动

### 4.1 前提：配置与数据库

```bash
./bin/k8s-ai config init           # 生成 ~/.k8s-ai/config.yaml（已有文件需 --force）
./bin/k8s-ai config validate --config ~/.k8s-ai/config.yaml
# 期望：config OK: server version v1.28.x
```

保证配置文件里 LLM 网关可用（Chat 依赖）：

```yaml
llm:
  endpoint: "https://你的网关/v1"   # 或本地 vLLM/Qwen 地址
  api_key: ""                       # 也可用环境变量 K8S_AI_LLM_API_KEY
  model: "qwen-plus"                # 如果是本地模型改实际模型名
```

平台使用单一数据库文件 `~/.k8s-ai/k8s-ai.db`，身份、Session、审批与审计共享同一 Store。
默认单副本运行，避免 SQLite 多进程并发写锁。

### 4.2 Linux 启动

先建日志目录：

```bash
mkdir -p ~/.k8s-ai/logs
```

启动平台后端（server，8889 只是示例，也可用 8080 默认值）：

```bash
# 首次启动必选：初始化 admin 账号的密码；之后复用同一数据库可省略
export K8S_AI_ADMIN_PASSWORD='你的强密码'

# 可选：集群凭据加密密钥；未设置时集群端点只返回 501，其余能力正常
export K8S_AI_ENC_KEY='你的加密密钥'

nohup ./bin/k8s-ai server \
  --addr 0.0.0.0:8889 \
  --db "$HOME/.k8s-ai/k8s-ai.db" \
  --config "$HOME/.k8s-ai/config.yaml" \
  > "$HOME/.k8s-ai/logs/k8s-ai-server.log" 2>&1 &
echo $! > "$HOME/.k8s-ai/logs/k8s-ai-server.pid"
```

### 4.3 Windows 启动

PowerShell 前台启动：

```powershell
$env:K8S_AI_ADMIN_PASSWORD = "你的强密码"        # 首次启动必选
$env:K8S_AI_ENC_KEY        = "你的加密密钥"      # 可选

.\bin\k8s-ai.exe server --addr 0.0.0.0:8889 --db "$HOME\.k8s-ai\k8s-ai.db" --config "$HOME\.k8s-ai\config.yaml"
```

PowerShell 后台隐藏窗口方式（无人值守/测试用）：

```powershell
$env:K8S_AI_ADMIN_PASSWORD = "你的强密码"

Start-Process -FilePath ".\bin\k8s-ai.exe" `
  -ArgumentList @("server","--addr","0.0.0.0:8889","--db","$HOME\.k8s-ai\k8s-ai.db","--config","$HOME\.k8s-ai\config.yaml") `
  -RedirectStandardOutput "$HOME\.k8s-ai\logs\k8s-ai-server.out.log" `
  -RedirectStandardError  "$HOME\.k8s-ai\logs\k8s-ai-server.err.log" `
  -WindowStyle Hidden
```

### 4.4 Windows 下用 CMD（可选）

```cmd
set K8S_AI_ADMIN_PASSWORD=你的强密码
start "k8s-ai-server" /b bin\k8s-ai.exe server --addr 0.0.0.0:8889 --db %USERPROFILE%\.k8s-ai\k8s-ai.db --config %USERPROFILE%\.k8s-ai\config.yaml
```

## 5. 启动后验证

### 5.1 平台后端（server）

```bash
curl -s http://127.0.0.1:8889/healthz        # 期望 ok
curl -s http://127.0.0.1:8889/version        # 期望 {"version":"DEV-v4.0.0",...}
# 登录冒烟（首次启动后 admin 密码即时生效）
curl -s -X POST http://127.0.0.1:8889/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"你的强密码"}'
```

### 5.2 平台 Chat 与新前端

- 生产形态 A：浏览器访问 `k8s-ai server`，登录后使用 Chat；
- 本地开发：`cd web && npm run dev` 后打开 `http://localhost:5173`，`/api/v1`
  统一代理到平台后端，Chat Session 与 SSE 同属 `/api/v1/sessions*`。

### 5.3 进程存活检查

```bash
# Linux
ss -lntp | grep 8889
cat ~/.k8s-ai/logs/k8s-ai-server.pid

# Windows PowerShell
Get-NetTCPConnection -LocalPort 8889 | Select-Object LocalPort,State,OwningProcess
Get-Process k8s-ai
```

## 6. 停止服务

```bash
# Linux：按 PID 停
kill "$(cat ~/.k8s-ai/logs/k8s-ai-server.pid)"
# 或按命令行匹配
pkill -f 'k8s-ai server'
```

```powershell
# Windows PowerShell：按进程名全停（同名二进制会一并停止），或按 PID 精确停
Stop-Process -Name k8s-ai -Force
# 精确版：Get-Process k8s-ai | where { $_.Path -like '*k8s-ai.exe' } | Stop-Process
```

```cmd
REM Windows CMD：按 PID 终止（PID 从任务管理器或 netstat 查）
taskkill /F /IM k8s-ai.exe
```

## 7. 测试门禁（提交前）

### 7.1 后端 Go 测试

```bash
# 在仓库根目录执行
go vet ./...
go test ./...
go test -race ./...            # 可选，跑并发竞态
go test ./tests/arch/           # 架构边界（写路径只进 internal/executor、RBAC 只读约束等）

# Linux 下 gofmt 门禁（Makefile 里的 lint 目标）
make lint
```

> `make test` 等价 `go test ./...`，`make test-race` 等价 `go test -race ./...`。
> SQLite 是 pure-Go 驱动，Linux / Windows 都无需本地 gcc。

### 7.2 前端测试（在 `web/` 下）

```bash
cd web
npm run typecheck       # vue-tsc：TS 类型 + .vue 校验
npm run lint            # eslint
npm run test            # vitest run（单元/组件）
npm run build           # 生产构建能过 = 产物可打包
```

### 7.3 一条龙命令

```bash
# Linux
make build && go vet ./... && go test ./... && make lint
cd web && npm run typecheck && npm run lint && npm run test && npm run build

# Windows PowerShell
__build.cmd  # 或见 §2.2 手动 go build
go vet ./...
go test ./...
cd web; npm run typecheck; npm run lint; npm run test; npm run build
```

## 8. 常见问题定位

| 现象 | 原因与处理 |
| --- | --- |
| `k8s-ai server` 启动后立刻 `Exit 1` | 首次启动缺少 `K8S_AI_ADMIN_PASSWORD`。看 `k8s-ai-server.log`，有 `bootstrap admin ... must not be empty`。用 §4.2/§4.3 带密码启动一次完成 admin 引导；同一数据库后续启动可不再带。 |
| 登录页或 Chat 返回 401 | 确认所有 `/api/v1`（含 `/api/v1/sessions*`）都代理到同一 `server`，且请求携带当前登录 Token。 |
| `database is locked` | 平台默认单副本运行并使用单一 SQLite 文件；不要并行启动多个写入进程。 |
| 集群管理接口返回 501 | 未设置 `K8S_AI_ENC_KEY`（P3.x 凭据加密只从环境变量读取）；不影响其他能力。 |
| `config validate` 报集群连接失败 | 检查 kubeconfig / 集群 / 上下文；扫描需要只读权限。 |
| 新前端页面打不开 | 确认 `npm run dev` 已在 5173，平台后端 8080 存活。 |
| 构建产物 dist 无法直接访问 | 当前 `server` 尚未内嵌 SPA 静态资源，开发用 Vite，生产等待 P6.11，或按 §3.3 的 nginx 反代。 |
| 写操作未触发审批 | 默认 `agent.require_approval: true` 才弹审批卡；shell 语法命令永远走人工审批；`--skip-permissions`/`skip_permissions: true` 仅对非 shell 写操作放行。 |
